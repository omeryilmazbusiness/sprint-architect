SOLID rules:
- Controller only: validate + call usecase + respond
- Usecase only: orchestrates reads, no Drizzle queries
- Repo only: Drizzle queries, aggregation, joins
- DTOs: explicit output shape, stable for UI
- No circular imports, no duplicated clinic scoping logic

Backend endpoint:
- GET /v1/admin/dashboard
ADMIN only.

Return DTO (example):
{
  currentPeriod: "YYYY-MM",
  clinics: { active: number, suspended: number, total: number },
  invoices: {
    pending: number,
    unpaid: number,
    paid: number,
    totalBilledThisMonth: number
  },
  recentInvoices: [
    { id, clinicId, clinicName, period, total, status, createdAt }
  ],
  activity: [
    { id, type, message, createdAt }
  ]
}

Data rules:
- currentPeriod derived in Europe/Istanbul timezone.
- recentInvoices: last 5 invoices
- activity: last 5 audit log entries or derived billing events (neutral messaging)

If audit logs exist, use them; otherwise implement minimal activity source from invoices + clinic status transitions.
