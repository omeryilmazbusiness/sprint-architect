========================================================
C) BACKEND ENDPOINTS
========================================================
1) Purge impact preview (SUPER_ADMIN only)
GET /v1/admin/users/:id/purge-impact?entityType=ADMIN|MANAGER|PATIENT
Returns:
{
  canPurge: boolean,
  blockedReasons: string[],
  target: { id, entityType, email?, displayName, role?, clinicId? },
  dependencies: {
    refreshTokens: number,
    devices: number,
    credentialRequests: number,
    notifications: number,
    invoicesPaidBy: number,
    auditLogsActor: number,
    isPrimaryManager: boolean
  }
}
Rules:
- If self => canPurge=false with reason BLOCKED_SELF
- If primary manager => canPurge=false with reason PRIMARY_MANAGER_DELETE_BLOCKED
- If invoicesPaidBy/auditLogsActor > 0 => canPurge=false in STRICT mode

2) Purge execution (SUPER_ADMIN only)
DELETE /v1/admin/users/:id/purge
Body (zod):
{
  entityType: "ADMIN"|"MANAGER"|"PATIENT",
  confirmText: string,
  mode?: "STRICT"|"ANONYMIZE"
}
Rules:
- confirmText must match exactly:
  - For ADMIN/MANAGER: "PURGE <email>"
  - For PATIENT (no email): "PURGE <id>" or "PURGE <patientKey>"
Return 400 with CONFIRM_TEXT_MISMATCH if not.
Usecase:
- Recompute purge-impact and refuse if blocked.
- Run db.transaction:
  - delete refresh_tokens for target
  - delete devices for target (patients)
  - delete credential_requests where targetUserId/targetPatientId = target
  - delete notifications related to target (targetRole + relatedId if used)
  - If ANONYMIZE mode:
    - detach invoices/audit references safely
  - finally delete from users OR patients table
- Emit audit log:
  action: ADMIN_USER_PURGED
  metadata: { targetId, entityType, mode, blockedRefsCounts }
Return:
{ ok:true }

3) Standardized error codes (must be used)
- PURGE-001 BLOCKED_SELF
- PURGE-002 PRIMARY_MANAGER_DELETE_BLOCKED
- PURGE-003 BLOCKED_REFERENCES_EXIST
- PURGE-004 CONFIRM_TEXT_MISMATCH
- PURGE-005 FORBIDDEN_NOT_SUPER_ADMIN
