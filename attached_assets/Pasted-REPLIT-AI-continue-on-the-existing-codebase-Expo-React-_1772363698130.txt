B) BACKEND — ENDPOINTS (Express)
========================================================
1) Create credential request (public-ish but rate limited)
POST /v1/auth/credential-requests
Body (zod union):
A) Manager password request:
{ kind:"MANAGER_PASSWORD", email:string }
- Behavior:
  - Always return 200 with generic message (do not leak if email exists)
  - If email exists and role is MANAGER:
    - create credential_requests row linking targetUserId + clinicId
    - audit log: CREDENTIAL_REQUEST_CREATED
B) Guest access key request:
{ kind:"GUEST_ACCESS_KEY", guestAccessKey:string }
- Behavior:
  - If guestAccessKey matches a patient:
    - create request linking targetPatientId + clinicId
  - If not, still return 200 generic (no leakage)
Rate limit:
- 3 requests / 10 min / IP + identifier

2) Admin notifications list
GET /v1/admin/notifications/credential-requests?status=PENDING&limit=50
ADMIN only.
Returns list sorted newest first.

3) Admin unread count (for badge)
GET /v1/admin/notifications/unread-count
ADMIN only.
Count PENDING requests.

4) Admin resolve request: generate & send
POST /v1/admin/credential-requests/:id/resolve
Body:
{ action: "GENERATE_AND_SEND" }
ADMIN only.
Behavior depends on kind:
A) MANAGER_PASSWORD:
- generate a strong temp password (min 16 chars)
- set user.passwordHash = bcrypt(tempPassword)
- email temp password to user.email
- mark request COMPLETED, resolvedAt, resolvedByAdminId, sentToEmail
- audit log: CREDENTIAL_REQUEST_RESOLVED (include kind, userId)
- Return response includes a one-time plaintext password in response ONLY if you implement “one-time reveal”:
  { oneTimePassword?: "...." }
  IMPORTANT: Do not store this plaintext anywhere.

B) GUEST_ACCESS_KEY:
- generate new patientKey (non-guessable)
- reset device binding (revoke)
- email new key to clinic.contactEmail (must exist) OR to the clinic manager email if you store it; choose best available.
- mark request COMPLETED
- audit log: GUEST_ACCESS_KEY_REGENERATED
- Return { oneTimeAccessKey?: "...." } optionally one-time reveal.

5) Optional reject
POST /v1/admin/credential-requests/:id/reject
Body:{ reason?:string }
ADMIN only.
