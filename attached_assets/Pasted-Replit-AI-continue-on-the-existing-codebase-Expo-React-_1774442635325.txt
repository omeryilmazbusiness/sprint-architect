PHASE 2 — FIX THE DEPRECATED FILESYSTEM API (PROD-READY)
========================================================
Goal: remove deprecated warning WITHOUT breaking functionality.

Option A (recommended now, safest): use legacy API import
- Replace:
  import * as FileSystem from "expo-file-system"
  FileSystem.downloadAsync(...)
- With:
  import * as FileSystemLegacy from "expo-file-system/legacy"
  FileSystemLegacy.downloadAsync(...)
This removes the warning immediately while keeping behavior identical.

Option B (optional later): migrate to new File/Directory API
- Not required now.

Implement SOLID wrapper service:
Create:
src/services/files/FileService.ts (or app/services/files/FileService.ts)

Expose:
- downloadPdfToCache(url: string, filenameHint?: string): Promise<{ uri: string }>
- openPdf(uriOrUrl: string): Promise<void>
Rules:
- Use FileSystemLegacy.downloadAsync internally (Option A).
- Save to cache directory with safe filename.
- Then open the file:
  - iOS: Linking.openURL(fileUri)
  - Android: use Linking or expo-intent-launcher if required (only if already installed; otherwise try Linking first)
- Always catch errors and return user-friendly toast:
  “Could not open PDF. Please try again.”
  Include internal error code in dev logs.

Remove direct filesystem calls from UI components; they call FileService only.
