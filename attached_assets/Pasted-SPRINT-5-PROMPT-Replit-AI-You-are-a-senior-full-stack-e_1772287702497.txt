B) FEATURE 2 — AUTH PERSISTENCE (REMOVE IN-MEMORY RISK)
========================================================
Problem:
Audit report indicates refresh tokens / bindings may be in-memory. Sprint 5 must ensure that:
- Refresh tokens are persisted in PostgreSQL with rotation
- Device bindings persist and are enforced even after server restart
- Logout revokes refresh token

Requirements:
1) Refresh token persistence:
- Table refresh_tokens already exists or create it if needed:
  - id, userId nullable, patientId nullable, tokenHash, expiresAt, revokedAt, createdAt, replacedByTokenId nullable
- Never store raw refresh token; store a hash (SHA-256) or bcrypt hash.
- Implement rotation:
  - /v1/auth/refresh and /v1/patient/auth/refresh (if patient refresh exists; if not, keep shared refresh endpoint)
  - When refreshing: revoke old token, issue new token, link replacedByTokenId

2) Device binding persistence:
- Table devices should persist:
  - id, patientId, deviceId, boundAt, revokedAt nullable
- Login rule must be DB-driven:
  - If active binding exists and deviceId differs -> throw DEVICE_ALREADY_BOUND
  - Reset device marks revokedAt and allows re-bind

3) Tests:
- Add tests verifying:
  - refresh token rotation and revocation survives “simulated restart” (i.e., new repository instance still validates via DB)
  - patient device binding denies second device, allows after reset

C) FEATURE 3 — INVOICING MVP (MONETIZATION FOUNDATION)
========================================================
Goal:
Generate monthly invoices per clinic based on number of patients created/active in that month.
Expose endpoints for ADMIN and MANAGER to view invoices.

Business rules (MVP):
- Billing period = YYYY-MM
- Patient count = number of patients created within that period for that clinic
- Unit price = clinic.billingUnitPrice (add field) OR global env default
- total = patientCount * unitPrice
- Invoice statuses: DRAFT, ISSUED, PAID (MVP)

DB models (Drizzle):
- clinics: add billingUnitPrice (nullable), currency default "EUR"
- invoices:
  - id, clinicId, period (YYYY-MM), patientCount, unitPrice, currency, total, status, createdAt
  - unique(clinicId, period)
- invoice_events (optional audit):
  - id, invoiceId, action, actorId, actorRole, createdAt

Backend endpoints:
ADMIN:
- POST /v1/admin/invoices/generate?period=YYYY-MM
  - Creates invoices for all clinics for that period (idempotent; upsert)
- GET /v1/admin/invoices?period=&clinicId=&status=
- GET /v1/admin/invoices/:id
- PUT /v1/admin/invoices/:id/status  body:{status}
MANAGER:
- GET /v1/manager/invoices?period=&status=
- GET /v1/manager/invoices/:id  (only own clinic)

Optional PDF (if time allows, otherwise Sprint 6):
- GET /v1/invoices/:id/pdf  (ADMIN + MANAGER own clinic)
Generate a basic PDF invoice with clinic name, period, counts, totals.

Mobile UI (minimal but real):
ADMIN (if admin is used in mobile):
- In Settings tab or a new Admin tab: Invoices list + filter by period
MANAGER:
- In Settings tab: “Invoices” screen listing invoices for own clinic + details
