B) BACKEND REQUIREMENTS (Express + Drizzle)
========================================================
1) Endpoints needed (verify existing, add if missing)
A) Manager — month appointments range
GET /v1/manager/appointments?from=ISO&to=ISO
Return:
[
  { id, startAt, title, status, patientId, patientName, doctorName? }
]
Clinic scoped.

B) Manager — guests list with filters
GET /v1/manager/patients?search=&status=&missing=&page=&pageSize=
- search case-insensitive on fullName and patientKey
- missing filter:
  - missingDoctor: patient_plan.doctorId is null
  - missingDocuments: exists patient_documents where status=ASSIGNED (Pending)
  - missingHotel/transport if your schema includes those
Return pagination metadata.

C) Manager — guest detail aggregate endpoint (IMPORTANT)
GET /v1/manager/patients/:id/details
Return a single payload:
{
  patient: {...},
  plan: { doctorId?, hotelId?, transportId?, checkIn/out?, roomNo? },
  doctor: {...} | null,
  documents: [ { id, typeName, status, fileUrl? } ],
  appointments: [ ... ],
  tracking: { currentStep, stepsComputed?, events: [...] }
}
This prevents multiple API calls and makes UI fast.

D) Manager — assign doctor
PUT /v1/manager/patients/:id/assign-doctor
body: { doctorId: string | null }
Validate doctor belongs to same clinic.

E) Manager — assign required documents (document types fixed)
POST /v1/manager/patients/:id/assign-documents
body: { documentTypeCodes: string[] }
Use codes like:
- PASSPORT_COPY
- VISA
- LAB_TESTS
Idempotent: don’t duplicate.

F) Manager — create appointment (already exists maybe)
POST /v1/manager/patients/:id/appointments
body: { title, type?, startAt, endAt?, doctorId?, locationText?, notes? }
