You are a principal full-stack TypeScript engineer. You will extend an existing monorepo that contains:
- Mobile: Expo React Native + expo-router
- Backend: Express + TypeScript
- Database: PostgreSQL + Drizzle ORM
- Existing: JWT access/refresh, roles (ADMIN/MANAGER/PATIENT), clinic scoping, invoices (basic), audit logs, rate limiting, PDF storage providers.

Your mission: build a production-grade **Admin Console** and enforce strict tenant rules so the system behaves like a true multi-tenant SaaS. You must first inspect the current codebase (routes, schema, middleware, repositories, existing invoice logic) and then implement changes with minimal regressions, strong typing, and clean architecture.

========================================================
NON-NEGOTIABLE BUSINESS RULES
========================================================
1) Tenant binding is mandatory:
   - Every MANAGER belongs to exactly ONE clinic (clinicId required, never null).
   - Every PATIENT belongs to exactly ONE clinic (already likely true; enforce consistently).
   - No manager/patient may ever exist without a clinic or switch across clinics without explicit admin action.

2) Clinic suspension is absolute:
   - If a clinic is SUSPENDED, then ALL its managers and patients MUST be blocked from using the app.
   - Blocking must apply to: login, refresh, and every protected API call (server-side enforced).
   - Admin users are not blocked by clinic status.

3) Billing automation:
   - Each clinic has a billing cadence based on its creation day-of-month.
     Example: clinic created on the 12th → invoices are generated on the 12th of each following month.
   - Invoices have full details (period, totals, status, issuedAt, dueAt, paidAt, clinic pricing).
   - If an invoice is not paid by dueAt, the clinic becomes SUSPENDED immediately.

4) Admin UX must be premium:
   - Admin dashboard must feel “enterprise SaaS”: clear navigation, strong information hierarchy, quick actions, and clinic-centric views.
   - After creating a clinic, the UI must immediately guide the admin to “Create Manager” (icon + CTA).

========================================================
A) Clinics
- Extend clinic_status enum to include: ACTIVE, INACTIVE, SUSPENDED (if not already).
- Add billing anchor fields if missing:
  - billingAnchorDay (int 1..28/31) OR derive from createdAt day-of-month and store it to avoid edge cases.
- Ensure clinics have:
  - billing_unit_price (nullable, fallback to DEFAULT_UNIT_PRICE)
  - currency (default "EUR")

B) Users

- Add optional metadata if helpful:
  - mustChangePassword (boolean) for first login (recommended).

C) Invoices
Enhance invoice schema with operational billing fields:
- issuedAt (timestamp)
- dueAt (timestamp) — controls suspension logic
- paidAt (timestamp, nullable)
- status: DRAFT | ISSUED | PAID | OVERDUE (optional; if you keep only DRAFT/ISSUED/PAID then compute overdue via dueAt)
- period remains YYYY-MM
- Ensure uniqueness: (clinicId, period) unique constraint

All schema changes must be implemented in shared/schema.ts and migrated via existing drizzle workflow.

========================================================
SECURITY & MIDDLEWARE — MUST IMPLEMENT
========================================================
Implement a middleware that blocks suspended clinics:
- `requireActiveClinic()` applied to:
  - all MANAGER routes
  - all PATIENT routes
  - auth refresh endpoints (manager/patient)
  - patient login endpoint
  - manager login endpoint
Rules:
- If actorRole is ADMIN: bypass.
- Otherwise load clinic by clinicId and if status === SUSPENDED → return 403 with code CLINIC_SUSPENDED.

Also ensure device binding, token rotation and existing RBAC remain intact.

========================================================
BILLING AUTOMATION — REQUIRED
========================================================
Implement an automated invoice scheduler and suspension enforcer.

A) Invoice Generation Logic
For each ACTIVE clinic:
- Determine “current billing period” (YYYY-MM) based on today’s date.
- If today is on/after the clinic’s billingAnchorDay for the current month AND invoice for that period does not exist:
  - Create invoice (prefer ISSUED) with:
    - issuedAt = now
    - dueAt = issuedAt + GRACE_DAYS (env; default 7)
    - unitPrice = clinic.billingUnitPrice or DEFAULT_UNIT_PRICE
    - patientCount = per existing logic (e.g., patients created in that period; keep current business rule unless stated otherwise)
    - total = patientCount * unitPrice
- Invoice creation must be idempotent.

B) Overdue Detection & Suspension
On a frequent schedule (at least daily):
- Find invoices where status != PAID and dueAt < now.
- Immediately set their clinic status to SUSPENDED.
- Optionally mark invoice status to OVERDUE (if implemented).
- When an invoice becomes PAID, automatically re-activate clinic (ACTIVE) unless clinic is INACTIVE for other reasons.

C) Execution Model
Because Replit may not guarantee traditional cron:
- Implement BOTH:
  1) A lightweight in-process scheduler using node-cron (or setInterval) to run every day/hour, AND
  2) A “lazy catch-up” trigger: on admin dashboard load AND on login/refresh, call a safe function that checks generation/overdue for the relevant clinics (admin for all clinics; manager/patient for their clinic).
This guarantees correctness even if the process sleeps.

D) Audit Logging
Log these actions:
- invoice.generated
- invoice.status_changed
- clinic.suspended_due_to_unpaid_invoice
- clinic.reactivated_after_payment
- user.created / password_generated
